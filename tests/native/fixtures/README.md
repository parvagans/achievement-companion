# Synthetic Nintendo disc fixtures

The raw GameCube and Wii images are generated by
`tests/native/generate_nintendo_disc_fixtures.py`. They contain only test data.
The RVZ, WIA, and GCZ files were converted from those images with Dolphin
development tooling. The Nintendo CISO and WBFS files were converted from the
same images with `nodtool` and gzip-compressed for repository storage. Dolphin
and `nodtool` are fixture-generation tools only; neither is called by the
installed plugin.

The encrypted Wii fixture starts from `make_wii_hashed`, which creates a
decrypted partition with valid H0/H1/H2/H3 blocks. Pinned `nodtool` then
converted it to an encrypted ISO, RVZ, and WIA. The encrypted ISO is stored as
`synthetic-wii-encrypted.iso.gz`. An earlier probe with zeroed partition hash
blocks produced different hashes after RVZ conversion; that invalid probe is
not a reference fixture.

`tests/native/test_ra_hash.py` regenerates the raw images, hashes them with the
packaged `ac-rhash`, and compares the hashes against every compressed fixture.
It also creates a minimal PS2 ISO9660 boot image in memory and compares its
hash with a sparse image over 4 GiB, proving the direct-disc path has no
file-size cutoff without storing a large fixture.
The expected GameCube hash is `a52044325b45b9690b04ccaa876874af`; the
expected Wii hash is `741e1d5e77c4fa126bc0dc8bb61d022d`. Both values were
obtained independently from the raw images using pinned rcheevos.

The test checks both decrypted and encrypted Wii branches. The encrypted
reference hash is `d031ee339c2c0d7d7f79fc91815781c5`, and raw ISO, RVZ,
and WIA must all return it. The reader requests nod's original logical disc
representation so rcheevos sees the appropriate partition data and header.
